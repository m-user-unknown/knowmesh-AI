# knowmesh-AI

A local personal knowledge base and RAG assistant that turns your documents into searchable, source-grounded answers using a LangGraph workflow, Chroma vector search, and Groq-hosted model inference.

## What this project does

- Loads PDFs and Markdown files from `Data/Docs`
- Splits documents into chunks and embeds them with `sentence-transformers/all-MiniLM-L6-v2`
- Stores the indexed chunks in a local Chroma database at `chroma_db/`
- Uses a multi-step LangGraph agent in `app.py` to:
  - rewrite the user query for better retrieval
  - fetch the most relevant documents
  - grade each retrieved document for relevance
  - answer using only relevant context
- Shows the final answer in a Streamlit chat interface with source filenames cited

This is a lightweight personal "second brain" prototype for document Q&A and retrieval-based knowledge search.

## What changed in `app.py`

The app is no longer a basic single-step retrieval chatbot. It now includes a LangGraph-based agent workflow:

- `rewrite_query()` reformulates the question before semantic search
- `retrieve_documents()` fetches candidate passages from Chroma
- `grade_documents()` filters out weak or irrelevant results using an LLM check
- `generate_answer()` returns a grounded answer based only on relevant retrieved context
- `should_generate()` controls whether the app generates an answer or returns a "no relevant docs" response
- `build_graph()` compiles the workflow and runs it through a Streamlit chat session
- Chat history is kept in `st.session_state`, and debug information is exposed in an expandable panel

The app also sets a specific model and RAG pipeline:

- LLM: `openai/gpt-oss-20b` via `langchain_groq.ChatGroq`
- Embeddings: `sentence-transformers/all-MiniLM-L6-v2`
- Vector DB collection: `knowmesh`
- Retriever: top 6 results

## Project structure

- `app.py` — Streamlit app with the LangGraph retrieval and answer pipeline
- `ingest.py` — document ingestion pipeline that loads files, chunks them, and indexes them in Chroma
- `Data/Docs/` — place your PDFs and Markdown files here
- `chroma_db/` — persisted local vector database generated by the ingestion step
- `requirements.txt` — Python dependencies
- `LICENSE` — MIT license

## Prerequisites

- Python 3.10+
- pip
- A Groq API key

## Setup

1. Create and activate a virtual environment:
   ```bash
   python -m venv .venv
   source .venv/bin/activate
   ```

2. Install dependencies:
   ```bash
   pip install -r requirements.txt
   ```

3. Configure your environment variables in a `.env` file:
   ```env
   GROQ_API_KEY=your_groq_api_key_here
   ```

## Ingest your documents

Place your PDFs and Markdown files in `Data/Docs`, then run:

```bash
python ingest.py
```

This creates or updates the local Chroma index at `chroma_db/`.

## Run the app

```bash
streamlit run app.py
```

Then open the local URL shown by Streamlit and ask questions about your documents.

## Behavior notes

- The app is designed for personal local use and stores the vector DB on disk.
- Embeddings are generated locally via Hugging Face, while the LLM calls are handled through Groq.
- Responses are grounded in retrieved context, and when no relevant document is found, the app clearly states that.
- Source filenames are included in the generated answer context to help trace the answer back to the original document.
